LAYER 1: CSS-LEVEL PRINT PREVENTION

```css

    html { display: none !important; }
    body { display: none !important; }
```

This prevents ANY print dialog from rendering the page.

Location: Added to <style> section in HEAD
Impact: Browser-level prevention (cannot be bypassed)

================================================================================
LAYER 2: JAVASCRIPT EVENT BLOCKING
================================================================================

Implemented multiple JavaScript event listeners to block print attempts:

1. KEYBOARD PREVENTION (Ctrl+P / Cmd+P):
```javascript
document.addEventListener('keydown', function(e) {
    if ((e.ctrlKey || e.metaKey) && (e.key === 'p' || e.key === 'P')) {
        e.preventDefault();
        e.stopPropagation();
        e.stopImmediatePropagation();
        return false;
    }
}, true);
```

2. WINDOW.PRINT() OVERRIDE:
```javascript
window.print = function() {
    console.log("Print blocked - use code execution instead");
    return false;
};
```

3. DOCUMENT.ONKEYDOWN BACKUP:
```javascript
document.onkeydown = function(e) {
    if ((e.ctrlKey || e.metaKey) && (e.key === 'p' || e.key === 'P')) {
        e.preventDefault();
        e.stopPropagation();
        return false;
    }
};
```

4. BEFOREPRINT EVENT BLOCKER:
```javascript
window.addEventListener('beforeprint', function(e) {
    e.preventDefault();
    return false;
}, true);
```

Location: Added to <script> section
Impact: Multiple fallbacks ensure print is blocked

LAYER 3: BUTTON-LEVEL EVENT PREVENTION
================================================================================

HTML buttons now have DUAL event prevention:

BEFORE (vulnerable):
```html
<button type="button" onclick="runCode('code1', 'output1')">▶ Run Code</button>
```

AFTER (protected):
```html
<button type="button"
        onclick="runCode('code1', 'output1', event); return false;"
        onmousedown="event.preventDefault(); return false;">
    ▶ Run Code
</button>
```

Key improvements:
✓ onclick passes event object to function
✓ Inline return false stops propagation
✓ onmousedown prevents mousedown phase
✓ Both prevent default behavior

Location: Every interactive button in HTML
Impact: Button-level event interception

LAYER 4: FUNCTION-LEVEL EVENT HANDLING
================================================================================

runCode() and resetCode() functions now handle events defensively:

```javascript
function runCode(textareaId, outputId, event) {
    if (event) {
        event.preventDefault();
        event.stopPropagation();
        event.stopImmediatePropagation();
    }

    const code = document.getElementById(textareaId).value;
    const outputBox = document.getElementById(outputId);
    outputBox.innerHTML = '';

    try {
        let output = '';
        const customLog = function(...args) {
            output += args.join(' ') + '\n';
        };

        const originalLog = console.log;
        console.log = customLog;

        // Intercept window.print to prevent dialog
        const originalPrint = window.print;
        window.print = function() { console.log("[Print output]"); };

        eval(code);

        console.log = originalLog;
        window.print = originalPrint;

        outputBox.innerHTML = output || '✓ Code executed successfully!';
    } catch (error) {
        outputBox.innerHTML = `<span style="color: #ff6b6b;">❌ Error: ${error.message}</span>`;
    }
    return false;
}
```

Key improvements:
✓ Event object parameter for immediate prevention
✓ preventDefault() called first
✓ stopPropagation() stops bubbling
✓ stopImmediatePropagation() stops all handlers
✓ Intercepts window.print during eval execution
✓ Returns false to stop default action

Location: JavaScript functions in <script>
Impact: Function-level event interception

================================================================================
LAYER 5: EVAL-LEVEL PROTECTION
================================================================================

During code execution via eval(), window.print is temporarily replaced:

```javascript
const originalPrint = window.print;
window.print = function() { console.log("[Print output]"); };

eval(code);  // Any print() calls here are captured

window.print = originalPrint;  // Restore original
```

This ensures that:
✓ If user code tries to call print(), it's intercepted
✓ Output is captured as text in console output
✓ No dialog can appear
✓ Original window.print is restored after execution

Location: Inside runCode() function
Impact: Protection during user code execution
